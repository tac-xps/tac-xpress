# Security audit

Reviewed 2026-11-13 against TAC-XPRESS source at `98f3e42`. Findings cite the operation boundary. Hosted checks used the exact project configured in `.env.local` and read catalog metadata only. See [database audit](database-audit.md) for RLS, grants, and routine details.

## Findings

| ID | Priority and evidence | Impact, mitigation, and verification |
| --- | --- | --- |
| SEC-01 | P1 · **VERIFIED in source**. Seven staff MFA management actions in [mfa-actions.ts](../../app/actions/mfa-actions.ts) checked for a signed session ID. They omitted the live `users` role and soft-delete check in the [workspace authorization guard](../../lib/auth/guards.ts). | A revoked session could continue to read and change its own MFA state until expiry. **Fixed locally.** The shared action guard now covers settings, TOTP setup and removal, and passkey enrollment and removal. The pre-authentication challenge flow remains separate. [Role regression](../../__tests__/current-role-guards.test.ts). |
| SEC-02 | P2 · **VERIFIED hosted advisor finding**. Supabase Auth reports leaked password protection disabled on the configured project. | Review supported configuration and plan entitlement. Enable with owner authorization and verify staging password enrollment and change behavior. [Supabase password security](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). |
| SEC-03 | P2 · **VERIFIED in source**. Fleet telemetry authorizes a single shared integration credential and accepts any registered active vehicle ID or registration. [Telemetry route](../../app/api/fleet/telemetry/route.ts), [mobile client guard](../../lib/auth/verify-mobile-client.ts). | Credential scope spans the fleet. Define the device or driver assignment contract before changing clients. Verify authorized vehicle reporting, denial for out-of-assignment vehicles, and token revocation in synthetic staging. |
| SEC-04 | P1 · **VERIFIED**. Password sign-in previously reconciled mismatched IDs by email. Three active workspace records have no matching Supabase Auth account. [Credentials authorization](../../auth.ts). | **Fixed locally.** New staff sessions require the canonical Auth ID. Local Supabase config disables signup. Hosted signup still reports enabled. Review the unmatched records and test staging before promotion. |
| SEC-05 | P2 · **VERIFIED in source**. [Active browser instrumentation](../../instrumentation-client.ts) opted into default PII and installed Sentry Replay unconditionally. The [legacy configuration](../../sentry.client.config.ts) gates Replay with the documented `NEXT_PUBLIC_SENTRY_REPLAY_ENABLED` variable. | **Fixed locally.** The active browser entry point now honors the Replay opt-in, explicitly masks text and inputs, blocks media, and disables default PII. [Mocked SDK regression](../../__tests__/client-instrumentation.test.ts). Actual hosted telemetry capture and redaction remain **UNVERIFIED**. [Sentry options](https://docs.sentry.io/platforms/javascript/guides/nextjs/configuration/options/), [Replay privacy](https://docs.sentry.io/platforms/javascript/guides/nextjs/session-replay/privacy/). |
| SEC-06 | P1 · **VERIFIED in source**. [Public tracking projection](../../lib/tracking/public-query.ts) used a left join, so an active shipment could return route and service metadata without a published event. Public support consumes the same projection. | **Fixed locally.** The shared projection now requires an explicitly public event. Historical shipments without a public event stay hidden until staff publish an event. [Projection regression](../../__tests__/data-projections.test.ts). |

## Controls and evidence

- **VERIFIED in source** — The shared guard checks current staff roles across protected pages, actions, and APIs. Admin-only paths pass the explicit admin role. Public tracking returns the published-event projection. The signed invoice renderer uses document-bound, purpose-scoped, expiring tokens. [Authorization guards](../../lib/auth/guards.ts), [tracking projection](../../lib/tracking/public-query.ts), [document token](../../lib/auth/document-token.ts).
- **VERIFIED in source** — The proxy applies Arcjet protection, fails closed for private routes and mutations when production protection fails, and retains read-only public availability. Cargo upload uses the staff guard, origin check, record lookup, size limit, file signature checks, and auditing. Carrier and WhatsApp routes use integration authentication and bounded payloads. The carrier route acknowledges same-status updates and rejects custody changes. WhatsApp persists replay controls. [Proxy](../../proxy.ts), [upload route](../../app/api/cargo-documents/%5Bentity%5D/%5Bid%5D/route.ts), [webhooks](../../app/api/webhooks).
- **VERIFIED hosted metadata** — RLS covers every public and Storage table, the sole bucket is private, and the only public policies are limited to authenticated own-profile access. Metadata evidence and historical staging behavior are listed in the [database audit](database-audit.md).
- **VERIFIED historical staging receipt** — On runtime `8676eaa`, synthetic sign-ins showed customer session denial, staff admin-page denial, and current page/API revocation with an existing cookie. The same runtime passed private invoice creation and download checks. The original checkout retains the eleven-scenario receipt under `docs/audit-evidence/hosted-release-acceptance-2026-11-04.json`.
- **UNVERIFIED for the current release candidate** — Managed Auth provisioning behavior, provider send acceptance, the deployed request perimeter, and the full staff/admin/revoked role matrix require a run against the candidate on approved staging. Development test-auth branches are environment-gated in source. Confirm the real runtime environment and fixture database before running any mutation suite.

Review references include [Next.js data security](https://nextjs.org/docs/app/guides/data-security) and the [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html).
